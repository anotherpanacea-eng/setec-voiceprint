### Added

**Packaging P1 (`specs/svp-packaging-conversion.md`) — zero-install package skeleton and CI gates, no production module moves.** Lands `scripts/setec/` (the empty `contract/`/`core/`/`surfaces/`/`calibration/`/`external_mirror/`/`replication/` package skeleton) and `setec.paths` (`find_plugin_root()` plus named stay-put data-path accessors, including `scripts_dir()`); `pytest.ini`'s single scripts-root `pythonpath` plus the AST codemod that drops the now-redundant per-test-file `sys.path` bootstrap across 245 test files; `tools/check_packaging_migration.py` (the `__file__`-anchor migration checker, `--strict` mode with a shrink-only merge-base ratchet and ghost-row rejection, plus the single `packaging_migration_exemptions.yaml`); `tools/check_claim_license_guard.py` (the no-change claim-license deficit lock, with a structural — never substring — AST rename for a declared `moves` relocation, and `packaging_move_map.json`); `tools/check_zero_install.py` (the bare-copy structural-reachability and direct-launcher-execution gate, with `setec_run.py`'s bare-copy dispatch limitation recorded as a documented, monitored known gap rather than fixture-shaped away). All three new gates run in CI (`.github/workflows/tests.yml`).

Hermetic backend test mode (`SETEC_HERMETIC_BACKEND=stub` for judge/embedding/surprisal backend construction) was built in this same round, found to collide with the claim-license guard's own protected-set closure (two of the three backend modules are legitimate protected suppliers), and dropped from this PR per build review — it continues on `build/svp-hermetic-mode` pending a short spec amendment recording the §3/§5 collision.

Also fixed in the same pass: `setec_run.py`'s dispatcher now reports a bare-copy dispatch miss as the honest `internal_error` (a dispatcher/environment fault) instead of `policy_refused` (a privacy-guard signal it never actually received).
